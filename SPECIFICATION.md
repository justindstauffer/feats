# Feats - Family Fitness Social App Specification

## Overview

Feats is a private family social media application focused on physical activity accountability. Family members post their daily physical activities ("feats"), share photos, and interact through comments and reactions. The app encourages healthy habits through streaks, challenges, and personal goals.

## Tech Stack

### Backend
- **Language:** Go
- **Framework:** Gin (HTTP router)
- **ORM:** GORM
- **Database:** SQLite3
- **Authentication:** bcrypt (password hashing), JWT (tokens), UUID (identifiers)
- **Storage:** Local filesystem (designed for S3 migration)
- **Deployment:** Digital Ocean Droplet

### Frontend
- **Platform:** iOS (latest versions only)
- **Framework:** SwiftUI
- **Push Notifications:** Apple Push Notification Service (APNs)
- **Dependencies:** Minimize third-party libraries

## Security

This section defines the security requirements and best practices for the Feats application. Security is a core requirement, not an afterthought.

### Security Principles

1. **Defense in Depth** - Multiple layers of security controls
2. **Least Privilege** - Users and processes get minimum required permissions
3. **Fail Secure** - Errors default to denying access
4. **Zero Trust** - Validate everything, trust nothing from client

---

### Authentication Security

#### Password Requirements

| Requirement | Value |
|-------------|-------|
| Minimum length | 12 characters |
| Maximum length | 128 characters |
| Complexity | At least 1 uppercase, 1 lowercase, 1 number, 1 special character |
| Common password check | Reject passwords from known breach lists (top 10k) |
| Password history | Cannot reuse last 5 passwords |

#### Password Hashing

- **Algorithm:** bcrypt
- **Cost factor:** 12 (adjustable based on hardware)
- **Salt:** Automatically generated by bcrypt (unique per password)

#### Account Lockout

| Setting | Value |
|---------|-------|
| Failed attempts before lockout | 5 |
| Lockout duration | 15 minutes (exponential backoff on repeated lockouts) |
| Lockout scope | Per account, not per IP |

#### Additional User Fields for Security

| Field | Type | Notes |
|-------|------|-------|
| failed_login_attempts | integer | Reset on successful login |
| locked_until | timestamp | Account lockout expiry |
| password_changed_at | timestamp | Track password age |
| force_password_change | boolean | Require change on next login |
| last_login_at | timestamp | Audit trail |
| last_login_ip | string | Audit trail (hashed or encrypted) |

#### JWT Security

**Access Token:**
- Algorithm: HS256 (HMAC-SHA256) minimum, RS256 preferred for production
- Expiry: 15 minutes
- Claims: `sub` (user_id), `role`, `iat`, `exp`, `jti` (unique token ID)
- Storage (iOS): Memory only, never persisted

**Refresh Token:**
- Format: Cryptographically random 256-bit token
- Storage (server): SHA-256 hash only, never store plaintext
- Storage (iOS): Keychain with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`
- Rotation: Issue new refresh token on each use, invalidate old one
- Family tracking: Detect refresh token reuse (indicates theft)

**Token Revocation:**
- Maintain blocklist for revoked access tokens (until natural expiry)
- Delete refresh token from database on logout
- Revoke all tokens on password change

#### Password Reset Security

- Reset tokens: Cryptographically random, 256-bit, single-use
- Token expiry: 1 hour
- Token storage: SHA-256 hash only
- Rate limit: 3 requests per hour per account
- No user enumeration: Same response whether email exists or not
- Invalidate token after use or password change

#### Session Management

- Single active session per device (configurable)
- Admin can view and revoke all user sessions
- Auto-logout after 30 days of inactivity

### Authorization Security

#### Role-Based Access Control (RBAC)

```
Admin:
  - All User permissions
  - Create/delete users
  - View soft-deleted content
  - Access admin endpoints
  - Revoke any user session
  - Delete any content

User:
  - Create/read/update/delete own posts
  - Create/read/update/delete own comments
  - React to any post
  - Create/join/leave challenges
  - Manage own goals
  - View other users' public content
```

#### Resource Ownership

- Every mutable resource has an `owner_id` (user_id)
- Middleware validates ownership before allowing updates/deletes
- Admin role bypasses ownership checks
- UUIDs are validated format before database queries

#### Authorization Checks

```go
// Pseudocode for authorization middleware
func AuthorizeResource(userID, resourceOwnerID, userRole string) bool {
    if userRole == "admin" {
        return true
    }
    return userID == resourceOwnerID
}
```

### Input Validation & Sanitization

#### General Rules

- **Validate early:** Check all input at API boundary
- **Whitelist approach:** Define what IS allowed, reject everything else
- **Type coercion:** Enforce expected types (string, int, UUID, etc.)
- **Length limits:** Enforce maximum lengths on all string fields
- **Character restrictions:** Alphanumeric + limited special chars for usernames

#### Field-Specific Validation

| Field | Validation Rules |
|-------|-----------------|
| email | RFC 5322 format, max 254 chars, lowercase normalized |
| name | 1-100 chars, Unicode letters/spaces/hyphens only |
| bio | Max 500 chars, strip HTML tags |
| description (post) | Max 2000 chars, strip HTML tags |
| comment content | Max 1000 chars, strip HTML tags |
| activity name | 1-50 chars, alphanumeric + spaces |
| UUID params | Valid UUID v4 format, reject malformed |
| pagination | page >= 1, per_page 1-100 |
| dates | ISO 8601 format, reasonable range |

#### SQL Injection Prevention

- **GORM parameterized queries:** Never use string concatenation
- **Prepared statements:** All queries use placeholders
- **Input type enforcement:** UUIDs validated before queries

```go
// CORRECT - Parameterized
db.Where("id = ?", userID).First(&user)

// WRONG - String concatenation (never do this)
db.Where("id = " + userID).First(&user)
```

#### XSS Prevention

- Strip HTML from all user input on server
- Escape output in API responses (JSON encoding handles this)
- iOS app should not render HTML from API

### API Security

#### HTTPS Enforcement

- **TLS version:** 1.2 minimum, 1.3 preferred
- **Certificate:** Valid certificate from trusted CA (Let's Encrypt)
- **HSTS:** Enable with `max-age=31536000; includeSubDomains`
- **Redirect:** All HTTP requests redirect to HTTPS

#### Security Headers

| Header | Value |
|--------|-------|
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `X-XSS-Protection` | `1; mode=block` |
| `Content-Security-Policy` | `default-src 'none'; frame-ancestors 'none'` |
| `Cache-Control` | `no-store` (for authenticated responses) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |

#### CORS Configuration

```go
// Strict CORS - only allow iOS app
AllowOrigins:     []string{} // No browser origins (API-only)
AllowMethods:     []string{"GET", "POST", "PUT", "DELETE"}
AllowHeaders:     []string{"Authorization", "Content-Type"}
AllowCredentials: false
MaxAge:           86400
```

#### Rate Limiting

| Endpoint Category | Limit | Window |
|-------------------|-------|--------|
| Login | 5 requests | 15 minutes |
| Password reset | 3 requests | 1 hour |
| API (authenticated) | 100 requests | 1 minute |
| Image upload | 20 requests | 1 hour |
| Post creation | 30 requests | 1 hour |

Implementation:
- Token bucket algorithm
- Per-user rate limiting (by user_id for authenticated, by IP for unauthenticated)
- Return `429 Too Many Requests` with `Retry-After` header
- Store rate limit state in memory (or Redis for distributed)

#### Request Size Limits

| Limit | Value |
|-------|-------|
| Max request body (JSON) | 1 MB |
| Max request body (multipart/image) | 50 MB |
| Max header size | 8 KB |
| Request timeout | 30 seconds |
| Image upload timeout | 120 seconds |

#### API Versioning

- URL-based versioning: `/api/v1/...`
- Deprecation policy: 6 months notice before removing old versions

### File Upload Security

#### Image Validation

1. **File extension check:** Only `.jpg`, `.jpeg`, `.png`, `.heic`
2. **MIME type check:** Validate `Content-Type` header
3. **Magic bytes check:** Verify file signature matches claimed type
4. **Image parsing:** Attempt to decode as image, reject if fails
5. **Dimension limits:** Max 8192x8192 pixels
6. **File size limit:** 50 MB before compression

#### Magic Bytes Validation

```go
var magicBytes = map[string][]byte{
    "jpeg": {0xFF, 0xD8, 0xFF},
    "png":  {0x89, 0x50, 0x4E, 0x47},
    "heic": {0x00, 0x00, 0x00}, // + "ftyp" check
}
```

#### Image Processing Security

- **Strip EXIF metadata:** Remove GPS, camera info, timestamps
- **Re-encode images:** Always re-encode to JPEG to sanitize
- **No SVG:** SVG can contain scripts, not allowed
- **Processing timeout:** 30 seconds max per image
- **Memory limits:** Cap memory usage during image processing

#### File Storage Security

- **Randomized filenames:** Use UUID, never user-provided names
- **Path traversal prevention:** Validate paths, no `..` allowed
- **Separate storage directory:** Outside web root
- **File permissions:** 0644 for images, 0755 for directories
- **No execution:** Storage directory mounted with `noexec` (Linux)

#### Serving Files Securely

- Serve via application, not directly via filesystem
- Set `Content-Type` explicitly
- Set `Content-Disposition: inline` or `attachment`
- Add `X-Content-Type-Options: nosniff`

### Logging & Audit

#### Security Event Logging

**Events to log:**
- Login success/failure (with IP, user agent)
- Password changes
- Password reset requests
- Account lockouts
- Admin actions (user creation, deletion)
- Authorization failures (403 responses)
- Rate limit triggers
- Suspicious activity patterns

**Log format:**
```json
{
    "timestamp": "2024-01-15T10:30:00Z",
    "level": "WARN",
    "event": "LOGIN_FAILED",
    "user_id": "uuid-or-null",
    "email": "redacted@example.com",
    "ip_hash": "sha256-of-ip",
    "user_agent": "iOS/17.0 Feats/1.0",
    "reason": "invalid_password",
    "attempt_count": 3
}
```

#### Log Security

- **No sensitive data:** Never log passwords, tokens, full emails
- **PII handling:** Hash or mask PII in logs
- **Log rotation:** Daily rotation, 90-day retention
- **Log access:** Restricted to admin only
- **Log integrity:** Append-only, consider log signing (future)

#### Audit Trail Table

#### Certificate Pinning

- Pin to leaf certificate or public key
- Include backup pins for certificate rotation
- Fail closed on pin validation failure
- Implementation via URLSession delegate

```swift
func urlSession(_ session: URLSession,
                didReceive challenge: URLAuthenticationChallenge,
                completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void) {
    guard let serverTrust = challenge.protectionSpace.serverTrust,
          let certificate = SecTrustGetCertificateAtIndex(serverTrust, 0) else {
        completionHandler(.cancelAuthenticationChallenge, nil)
        return
    }

    let serverPublicKey = SecCertificateCopyKey(certificate)
    let pinnedPublicKey = loadPinnedPublicKey()

    if serverPublicKey == pinnedPublicKey {
        completionHandler(.useCredential, URLCredential(trust: serverTrust))
    } else {
        completionHandler(.cancelAuthenticationChallenge, nil)
    }
}
```

```xml
    <false/>
</dict>
```

### Infrastructure Security

#### Server Hardening (Digital Ocean Droplet)

**SSH Security:**
- Disable password authentication
- Use SSH key only (Ed25519 preferred)
- Change default SSH port (optional, security through obscurity)
- Disable root login
- Use `fail2ban` for SSH brute force protection

```bash
# /etc/ssh/sshd_config
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
AllowUsers deploy
```

**Firewall (UFW):**
```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH (or custom port)
ufw allow 80/tcp    # HTTP (redirect to HTTPS)
ufw allow 443/tcp   # HTTPS
ufw enable
```

**System Updates:**
- Enable unattended security updates
- Schedule regular full updates (weekly review)

**Process Isolation:**
- Run application as non-root user
- Use systemd with security directives

```ini
# /etc/systemd/system/feats.service
[Service]
User=feats
Group=feats
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/feats /var/log/feats
```

#### Nginx Security (Reverse Proxy)

```nginx
# Security headers
add_header X-Frame-Options "DENY" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Content-Security-Policy "default-src 'none'; frame-ancestors 'none'" always;

# Rate limiting
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
limit_req zone=api burst=20 nodelay;

# Hide server version
server_tokens off;

# SSL configuration
ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
ssl_prefer_server_ciphers off;
ssl_session_timeout 1d;
ssl_session_cache shared:SSL:50m;
ssl_stapling on;
ssl_stapling_verify on;
```

#### Database Security

- Database file not accessible via web
- File permissions: `0600` (owner read/write only)
- Regular backups with encryption
- Backup files stored separately from main server

#### Secrets Management

- Environment variables for secrets (not in code)
- `.env` file with restricted permissions (0600)
- Consider DO App Platform secrets or HashiCorp Vault (future)
- Rotate secrets periodically (JWT secret annually minimum)

### Incident Response

#### Preparation

- Document all system access credentials securely
- Maintain contact list for incident response
- Regular backups tested for restoration

#### Detection Indicators

- Multiple failed login attempts from same IP
- Unusual API traffic patterns
- Unexpected admin actions
- Database query anomalies
- File system changes in application directories

#### Response Procedures

1. **Contain:** Isolate affected systems if needed
2. **Assess:** Determine scope and impact
3. **Eradicate:** Remove threat, patch vulnerability
4. **Recover:** Restore from clean backup if needed
5. **Review:** Document incident, update procedures

#### Breach Notification

- If user data compromised, notify affected users within 72 hours
- Document all incidents for future reference

## Soft Delete & Cleanup

### Soft Delete Policy
- Deleted content is marked with `deleted_at` timestamp
- Soft-deleted content is hidden from normal queries
- Admin can view soft-deleted content

### Hard Delete Policy
- Background job runs daily
- Content soft-deleted for more than 30 days is permanently removed
- Associated images are deleted from filesystem

## Database Schema (SQLite)

```sql
-- Users
CREATE TABLE users (
    id TEXT PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    name TEXT NOT NULL,
    profile_picture TEXT,
    bio TEXT,
    role TEXT NOT NULL DEFAULT 'user',
    failed_login_attempts INTEGER NOT NULL DEFAULT 0,
    locked_until DATETIME,
    password_changed_at DATETIME NOT NULL,
    force_password_change BOOLEAN NOT NULL DEFAULT FALSE,
    last_login_at DATETIME,
    last_login_ip_hash TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME
);

-- Refresh Tokens
CREATE TABLE refresh_tokens (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    token_hash TEXT NOT NULL,
    expires_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Activity Types
CREATE TABLE activity_types (
    id TEXT PRIMARY KEY,
    name TEXT UNIQUE NOT NULL,
    icon TEXT,
    is_system BOOLEAN NOT NULL DEFAULT FALSE,
    created_by TEXT,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (created_by) REFERENCES users(id)
);

-- Posts
CREATE TABLE posts (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    activity_type_id TEXT NOT NULL,
    description TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (activity_type_id) REFERENCES activity_types(id)
);

-- Post Images
CREATE TABLE post_images (
    id TEXT PRIMARY KEY,
    post_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    display_order INTEGER NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (post_id) REFERENCES posts(id)
);

-- Reactions
CREATE TABLE reactions (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    post_id TEXT NOT NULL,
    reaction_type INTEGER NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (post_id) REFERENCES posts(id),
    UNIQUE(user_id, post_id)
);

-- Comments
CREATE TABLE comments (
    id TEXT PRIMARY KEY,
    post_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    parent_id TEXT,
    content TEXT NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME,
    FOREIGN KEY (post_id) REFERENCES posts(id),
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (parent_id) REFERENCES comments(id)
);

-- Streaks
CREATE TABLE streaks (
    id TEXT PRIMARY KEY,
    user_id TEXT UNIQUE NOT NULL,
    current_streak INTEGER NOT NULL DEFAULT 0,
    longest_streak INTEGER NOT NULL DEFAULT 0,
    last_activity_date DATE,
    updated_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Challenges
CREATE TABLE challenges (
    id TEXT PRIMARY KEY,
    created_by TEXT NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    activity_type_id TEXT,
    target_count INTEGER NOT NULL,
    start_date DATE,
    end_date DATE,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (created_by) REFERENCES users(id),
    FOREIGN KEY (activity_type_id) REFERENCES activity_types(id)
);

-- Challenge Participants
CREATE TABLE challenge_participants (
    id TEXT PRIMARY KEY,
    challenge_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    progress INTEGER NOT NULL DEFAULT 0,
    completed_at DATETIME,
    joined_at DATETIME NOT NULL,
    FOREIGN KEY (challenge_id) REFERENCES challenges(id),
    FOREIGN KEY (user_id) REFERENCES users(id),
    UNIQUE(challenge_id, user_id)
);

-- Goals
CREATE TABLE goals (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    activity_type_id TEXT,
    target_count INTEGER NOT NULL,
    period TEXT NOT NULL,
    current_progress INTEGER NOT NULL DEFAULT 0,
    period_start DATE NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (activity_type_id) REFERENCES activity_types(id)
);

-- Device Tokens
CREATE TABLE device_tokens (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    device_token TEXT UNIQUE NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Password History (prevent reuse)
CREATE TABLE password_history (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    password_hash TEXT NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Audit Logs
CREATE TABLE audit_logs (
    id TEXT PRIMARY KEY,
    timestamp DATETIME NOT NULL,
    user_id TEXT,
    action TEXT NOT NULL,
    resource_type TEXT,
    resource_id TEXT,
    ip_hash TEXT,
    user_agent TEXT,
    details TEXT,
    success BOOLEAN NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- Rate Limiting (optional, can use in-memory)
CREATE TABLE rate_limits (
    id TEXT PRIMARY KEY,
    key TEXT NOT NULL,
    tokens INTEGER NOT NULL,
    last_refill DATETIME NOT NULL,
    UNIQUE(key)
);

-- Indexes
CREATE INDEX idx_posts_user_id ON posts(user_id);
CREATE INDEX idx_posts_created_at ON posts(created_at);
CREATE INDEX idx_posts_deleted_at ON posts(deleted_at);
CREATE INDEX idx_comments_post_id ON comments(post_id);
CREATE INDEX idx_reactions_post_id ON reactions(post_id);
CREATE INDEX idx_challenge_participants_challenge ON challenge_participants(challenge_id);
CREATE INDEX idx_goals_user_id ON goals(user_id);
CREATE INDEX idx_password_history_user_id ON password_history(user_id);
CREATE INDEX idx_audit_logs_user_id ON audit_logs(user_id);
CREATE INDEX idx_audit_logs_timestamp ON audit_logs(timestamp);
CREATE INDEX idx_audit_logs_action ON audit_logs(action);
CREATE INDEX idx_refresh_tokens_user_id ON refresh_tokens(user_id);
CREATE INDEX idx_refresh_tokens_expires_at ON refresh_tokens(expires_at);
```

## iOS App Structure

### Screens

1. **Login** - Email/password authentication
2. **Feed** - Scrollable list of family feats
3. **Post Detail** - Full post with comments and reactions
4. **Create Post** - Activity picker, photo upload, description
5. **Profile** - User profile, streak, goals, post history

- `FeatCard` - Post preview in feed

- `CommentThread` - Threaded comment display
- `StreakBadge` - Visual streak indicator
- `ChallengeCard` - Challenge progress display
- `ActivityPicker` - Activity type selector
- `ImageGrid` - Multi-image display (1-4 images)

### Networking

- URLSession for API calls
- Async/await patterns
- Automatic token refresh on 401
- Offline queue for failed requests (optional enhancement)

- Register with APNs on app launch
- Send device token to backend
- Handle notification taps to navigate to relevant content
